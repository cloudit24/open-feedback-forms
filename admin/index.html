MariaDB connection

Create an empty database on your MariaDB server first, and a user with rights on it (CREATE, ALTER, SELECT, INSERT, UPDATE is enough — this app never needs to create the database itself). Enter those details here.

Field keys

The catalog of questions available to every form (nationality, gender, experience ratings...). This is the only place field keys are defined or edited — a form's field editor can only pick from this list, never type a new one.

Language Labels

The two languages this app supports. The key (en/ar) is fixed — it's baked into every field key, option and form — but you can rename what each is called and set its reading direction, and that name is used everywhere this admin panel talks about it (the Language Labels checkboxes on a form's Manage panel, for instance).

Every existing field label, dropdown option and the public form's fixed text (Submit, error messages...) get auto-translated via the free LibreTranslate API when you add one — review the results afterward, since machine translation won't always be perfect.

Appearance

This colors the admin panel itself — buttons, tabs, the calendar picker's selected day — not any individual public feedback form (set each form's own colors and logo from its Manage panel instead).

Dark mode keeps its own light-on-dark text color no matter what's set here, so it stays readable.

Time & timezone

Every timestamp is stored in UTC no matter what's picked here — this only controls how dates and times are displayed in this admin panel (Submissions, Dashboard, CSV export) and in the date/time filters.

Reference only — a Python web app can't set the operating system's clock. Point this machine's own NTP client at this server so its clock (and every timestamp this app records) stays accurate.

SMTP

Shared mail server used to send every email alert — each form's own alert rules only pick a destination address, not a mail server.

Telegram

Create a bot with @BotFather and paste its token here — each alert rule then only needs the destination chat id.

Database disconnected alert

Fires once per outage if this app loses its database connection — kept separate from per-form alert rules since it has to work even when the database (where those rules live) is unreachable.

Full backup

Downloads one zip file with everything needed to restore this install: config.json (database credentials, admin account, session secret, app settings), every uploaded logo, and a full export of every database table as database.json. Store it somewhere private — it contains credentials and personal submission data.

Re-running the installer or updating the Docker image never touches your existing configuration or database on its own — this backup is for safekeeping and for moving the install somewhere else, not something you need before a routine update.

A role is a name plus a checklist of permissions. "Applies to all forms" makes every per-form permission apply everywhere; leave it off and assign specific forms per user instead. See docs/ROLES_AND_PERMISSIONS.md for the full model.

Each user signs in separately from the primary admin account and only ever sees what their role and assigned forms allow.

What are field keys?

A field key is one reusable question definition — its key (a stable internal id like nationality), its English and Arabic labels, its type (short text, dropdown, rating...), and its options if it's a dropdown.

Every form picks its questions from this shared catalog instead of typing them out each time. When a field key is added to a form, its current label/type/options are copied onto that form — so editing a key here changes what a future "+ Add a field" picks up, but doesn't retroactively change a question a form already added. Edit that form's own copy from its Questions list if you need to change wording on a form that's already using it.

New forms start with no questions at all — add whichever field keys the form actually needs from the Field keys tab or from the form's own Questions list.

Deleting a field key here only removes it from the catalog going forward; forms that already added it keep their existing questions and past submissions untouched.

Forms & branding

Each form is its own listener on its own port, with its own logo, colors, subtitle, questions and expiry date — set these from a form's Edit button (Questions/Branding/Alerts) and Manage button (name, port, languages, expiry). Point one reverse proxy or Cloudflare Tunnel hostname at each form's port to publish it. A disabled form moves to Archived forms at the bottom of the Forms tab — restore it any time, or permanently delete it (and everything it collected) once you're sure.

Languages

Every form supports English and Arabic out of the box. Configuration → Language Labels lets you rename either one and add further languages — new ones are auto-translated via the free LibreTranslate API where possible (add an API key there for real translation instead of blank placeholders), and every label stays editable afterward. A form only offers the languages its own Language Labels checkboxes have enabled.

Dashboard & submissions

The Dashboard's trend chart shows daily bars by default; pick both a From and To date within a 2-day span and it switches to an hourly 24h view instead, so you can see exactly when submissions came in on a given day. The Submissions tab lists every response you have access to, filterable by form, date range, language, status and free text — Download filtered results as CSV (top of that tab) exports exactly what's currently filtered, and opens correctly in Excel with Arabic text intact.

Roles & users (Administration tab)

Beyond the one primary admin account, you can create any number of additional users, each with a custom role — a checklist of permissions (view dashboard, view/export submissions, edit questions, edit branding, manage settings, manage alerts, ...) that either applies to every form or only to whichever forms that user is individually assigned. Clone on an existing user copies its role and form assignments as a starting point for a new one. See docs/ROLES_AND_PERMISSIONS.md in the repo for the full model.

Alerts

Configuration → Alerts holds the shared SMTP server and Telegram bot used to send every alert, plus the one global "database disconnected" alert. Each form's own Alerts panel then picks a destination for any of three triggers: a new submission, a daily digest, and that form reaching its expiry date — add as many rules as you need, mixing channels and triggers freely.

Appearance & time

Configuration → Appearance sets this admin panel's own primary/text colors (separate from any individual form's branding). Configuration → Time sets the timezone used to display dates here and an NTP server reference (this app can't change your OS clock itself).

What this app does

A self-hosted, bilingual feedback form platform. No external services are required beyond the MariaDB database you point it at. Run any number of independently branded forms, each on its own port, managed from one admin panel.

Highlights

  • English and Arabic out of the box, plus any language you add, auto-translated via LibreTranslate and RTL-aware throughout
  • Per-form branding: logo, colors, subtitle, custom questions, expiry date
  • Custom roles built from a permission checklist: full access, one form only, read-only, or any combination you need
  • SMTP and Telegram alerts: new submissions, daily digests, database disconnection, form expiry
  • Dashboard with a daily or hourly (24h) submissions trend, filterable by form, date, language and status
  • CSV export, Docker deployment, and a one-line installer
